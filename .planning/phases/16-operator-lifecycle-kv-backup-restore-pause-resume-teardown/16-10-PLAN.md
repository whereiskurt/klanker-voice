<objective>
Build `kv destroy` — tearing the AWS footprint down without silently eating data.

Purpose: this is the only irreversible command in the phase, and every guard in it exists
because of a specific way the teardown could go wrong. The backup must verify before anything is
touched, because a destroy that proceeds on a bad backup is unrecoverable. The ledger bucket must
be emptied deliberately, because it has no `force_destroy` and a `terraform destroy` would
otherwise fail partway through a teardown — a good accident that keeps transcripts from being
silently eaten, and one to handle rather than trip over. And the DIDs must be reported and left
alone, because `725-404-8283` and the toll-free `855-916-INFO` cannot be bought back.

Output: `kv/internal/app/cmd/destroy.go` with `NewDestroyCmd`, the sequenced orchestration, the
explicit bucket empty, the dependency-ordered destroy, the final report, its tests, registration
in `root.go`, and `docs/ops/destroy.md`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator terminal → an irreversible teardown | this is the only command in the phase whose effects cannot be undone from inside the tool |
| backup artifact → the decision to proceed | the verification result is the sole gate between "safe" and "unrecoverable" |

| kv process → VoIP.ms account | the DID inventory is read; the account is never mutated |
