<objective>
Assemble the pause stage into the operator-facing commands: `kv pause`, `kv resume`, and
`kv pause status`, each running the spec §5.3 flow end to end over the pieces built in 16-05,
16-06, and 16-07.

Purpose: this is where the stage becomes usable and where its two most surprising properties
have to be said out loud. First, `kv pause` deliberately does not touch the kill-switch — they
are orthogonal, and coupling them would produce a surprise on resume. Second, the money does
not all stop: during a long pause the ElevenLabs Pro subscription becomes the largest remaining
line item, and the completion report is the only place the operator will be reminded.

Output: `kv/internal/app/cmd/pause.go` with the three commands and the reporting, its tests,
registration in `root.go`, and `docs/ops/pause-resume.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator terminal → `main` branch and CI | one command commits, pushes, and triggers an infrastructure apply |
| kv completion report → operator's mental model of what is running and what is billing | the report is the only place several non-obvious facts are stated |
| pause mechanism ↔ kill-switch | two independent controls that would produce surprising behavior if coupled |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-08-01 | Tampering | committing and pushing to `main` without the operator having seen the change | high | mitigate | Without `--yes` the diff is displayed and an affirmative answer is required; a non-interactive stdin is a refusal, not an implied yes; both are asserted with byte-identity checks on the flag file (D-18). |
| T-16-08-02 | Elevation of privilege | coupling pause to the kill-switch, so a resume silently re-enables sessions the operator had deliberately stopped | high | mitigate | The kill-switch is a prohibition with a grep acceptance criterion, and the completion report states explicitly that it was not touched (D-24). |
| T-16-08-03 | Spoofing | reporting a successful resume while the stack still returns 503 | high | mitigate | The health wait gates the success line, and the no-success-before-health property is a separate test (D-22). |
| T-16-08-04 | Repudiation | an operator later unable to explain a capacity change or an unexpected bill | medium | mitigate | `--reason` is recorded in the commit body, the run id is reported, and the cost posture and ElevenLabs caveat are stated in every completion report (D-25). |
| T-16-08-05 | Information disclosure | the report or an error echoing credentials or environment content | medium | mitigate | Reporting composes only typed values from `PauseReport` and `DrainReport`; the underlying git and gh layers already carry the no-environment-in-errors invariant from 16-06. |
| T-16-08-06 | Denial of service | a pause left half-applied — flag flipped and pushed but the apply failed — leaving the operator unsure of the real state | medium | mitigate | `kv pause status` prints the flag value and the live per-service desired and running counts side by side, so a flag-versus-reality divergence is directly observable; the runbook documents the recovery. |
| T-16-08-07 | Elevation of privilege | widening the CI surface to make the pause easier to automate | medium | mitigate | No workflow file is modified; the existing required-reviewer rule remains the gate and its waiting state is surfaced rather than bypassed (D-23). |
</threat_model>
