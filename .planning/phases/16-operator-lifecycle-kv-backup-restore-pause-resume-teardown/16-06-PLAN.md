<objective>
Build the git and GitHub-Actions half of the pause orchestration: the preflight that refuses,
the commit and push to `main`, and the workflow dispatch that resolves a run id and streams it
to completion — all behind narrow interfaces so the refusal paths are unit-testable.

Purpose: `kv pause` commits to `main` and pushes, unattended, on the operator's behalf. D-18's
preflight is the entire safety story for that. "Refuse rather than commit onto a surprise" is
only real if every refusal path is proven, which is why dirty tree, wrong branch, stale origin,
and missing `gh` auth are each a named, tested outcome rather than one vague error.

Output: `kv/internal/app/cmd/lifecycle_git.go` and `lifecycle_gh.go` with their interfaces,
exec-backed implementations, and table-driven refusal tests.
</objective>

    `ErrPreflightGHAuth` from Task 1. `DispatchWorkflow` runs the gh workflow-run subcommand with
    the workflow name, a ref flag, and one field flag per entry in `inputs` sorted by key for

    keep waiting. Return nil only on a successful conclusion; any other terminal conclusion is an
    error naming the run id and the conclusion.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kv process → `main` branch of the shared repo | kv commits and pushes unattended; whatever is in the working tree at that moment is a candidate to ship |
| kv process → `gh` subprocess → GitHub Actions | dispatching a workflow that assumes an IAM role and applies infrastructure |
| GitHub Actions → live AWS infrastructure | the dispatched apply changes production compute capacity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-06-01 | Tampering | committing and pushing unrelated working-tree changes alongside the pause flip | high | mitigate | The dirty-tree preflight refuses before anything is staged, and `CommitPaths` stages only `SiteHCLRelPath`; both are asserted, including a zero-commit-call assertion on every refusal path (D-18). |
| T-16-06-02 | Tampering | pushing a pause on top of unpushed local commits or a diverged branch | high | mitigate | `SyncedWithOrigin` reports false for behind, ahead, and diverged, and stale-origin is a terminal refusal (D-18). |
| T-16-06-03 | Elevation of privilege | dispatching an infrastructure apply that bypasses human review | high | mitigate | kv dispatches the existing `terragrunt-apply.yml` unchanged; the `terraform-apply` environment's required-reviewer rule is untouched and its waiting state is explicitly surfaced to the operator rather than worked around (D-19/D-23). No workflow file is modified. |
| T-16-06-04 | Spoofing | attaching to the wrong workflow run and reporting someone else's outcome as the pause result | medium | mitigate | `LatestRunID` filters by workflow, by branch, and by a `notBefore` dispatch timestamp, and errors rather than guessing when no matching run appears. |
| T-16-06-05 | Information disclosure | a GitHub token or the process environment leaking into an error or a log line | high | mitigate | No token is read or constructed — `gh` owns its credential storage; a grep acceptance criterion asserts no token env var or `os.Environ` reference exists in the file. |
| T-16-06-06 | Denial of service | an unbounded poll loop hanging the operator's terminal | medium | mitigate | Run-id resolution is bounded by attempt count; run watching reports state changes continuously so a long wait is visibly a wait, not a hang. |
</threat_model>
