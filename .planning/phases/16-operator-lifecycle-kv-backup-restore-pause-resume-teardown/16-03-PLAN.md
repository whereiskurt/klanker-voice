<objective>
Build `kv restore` — the other half of the artifact contract. Read a backup zip, resolve every
destination live, drop the rows that must never come back, and write the rest idempotently.

Purpose: the three restore hazards in spec §4.7 are each a way a plausible-looking restore
silently produces a broken stack — writing to a bucket name that no longer exists, wedging the
quota gate with a stale concurrency lease, or leaving a half-finished restore that cannot be
safely re-run. Each is designed for explicitly here.

Output: `kv/internal/app/cmd/restore.go` with `NewRestoreCmd`, the ephemeral classifier, the
batched idempotent writer, the dry-run reporter, a round-trip test against 16-02's writer, and
`docs/ops/backup-restore.md` recording the D-13 ordering.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backup zip on local disk → kv process | a file that may have been moved, edited, or corrupted since it was written is the input to a bulk write |
| kv process → live DynamoDB tables and S3 ledger bucket | bulk writes into the production identity and transcript stores |
| terraform outputs → write destinations | the only legitimate source of destination names |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-03-01 | Tampering | restoring rows from a modified or corrupted archive | high | mitigate | `OpenBackupArchive` calls `VerifyBackupArchive` first and refuses on any digest, byte-count, row-count, missing-entry, or extra-entry mismatch. There is no unverified read path. |
| T-16-03-02 | Denial of service | a restored stale concurrency lease wedging the quota gate for a real user | high | mitigate | `IsEphemeralItem` classifies heartbeat leases by the UsageHeartbeat pk/sk template read from the live entity file, filtering is on by default, and the round-trip test asserts the lease is absent after restore (D-11). |
| T-16-03-03 | Tampering | writing into a wrong or stale bucket because the manifest's recorded name was trusted | high | mitigate | `RestoreReport` separates `Manifest*` provenance from `Resolved*` destinations, `RunRestore` reads destinations only from `LiveTargets`, and the report prints both so a divergence is visible (D-10). |
| T-16-03-04 | Elevation of privilege | restoring expired OIDC sessions, next-auth sessions, or verification tokens, reviving credentials that should be dead | high | mitigate | Session state, interaction state, login intents, next-auth sessions, and verification tokens are all classified ephemeral, and any item with a past TTL is dropped regardless of key shape (D-11). |
| T-16-03-05 | Tampering | a partial restore left in an unknown state after an interruption | medium | mitigate | Full-item `PutRequest` batches with `UnprocessedItems` re-submission and bounded backoff make a re-run converge; the idempotence assertion is a required test (D-12). |
| T-16-03-06 | Denial of service | a restore against a stack whose tables do not exist yet, producing confusing partial failures | medium | mitigate | A missing destination is a hard error naming the resource and the `terragrunt apply` step, raised before any write (D-13). |
| T-16-03-07 | Information disclosure | the restore report echoing personal data from restored rows | medium | mitigate | The report emits counts, table names, and bucket names only — never item contents. |
</threat_model>
