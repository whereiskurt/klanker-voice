<objective>
Lay the Stage A foundation that `kv backup` (16-02) and `kv restore` (16-03) both stand on:
the AWS client accessors kv does not yet have, the backup manifest schema and its checksum
helpers, and the live target-resolution seam that D-10 makes non-negotiable.

Purpose: D-05 (manifest contents) and D-10 (destinations resolved live, never from the
manifest) are cross-cutting contracts. Defining them once, here, is what stops 16-02 and
16-03 from each inventing their own — and what makes both testable without AWS (D-30).

Output: `kv/internal/app/cmd/lifecycle_manifest.go`, `kv/internal/app/cmd/lifecycle_targets.go`,
their tests, three new `Config` client accessors in `root.go`, the AWS SDK service modules in
`kv/go.mod`, and the `backups/` ignore entry (D-14). No new command surface.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell → `terragrunt output -json` subprocess | kv spawns a subprocess whose stdout it parses; the subprocess inherits the operator's AWS credentials and decrypts SOPS |
| terraform state (AWS) → kv process memory | resolved infrastructure identifiers cross into a local tool that later writes files |
| kv process → local filesystem / git repo | the `backups/` directory this plan gitignores is inside a git working tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01-01 | Information disclosure | `terragrunt output -json` error path in `lifecycle_targets.go` | high | mitigate | Error text includes only the unit directory and terragrunt stderr; never the process environment, never AWS credentials, never SOPS plaintext. Task 3 acceptance criteria assert the error shape. |
| T-16-01-02 | Information disclosure | future `backups/` artifact committed to git | high | mitigate | Task 1 lands the `backups/` `.gitignore` entry in the foundation plan, before 16-02 can write a single artifact (D-14). |
| T-16-01-03 | Tampering | a destination name sourced from an attacker- or drift-supplied manifest | high | mitigate | `LiveTargets` is the only destination type and is constructible only from `TerraformOutputReader`; the D-10 rule is recorded as a doc comment and asserted as an acceptance criterion (D-10). |
| T-16-01-04 | Elevation of privilege | new `S3Client` / `ECSClient` / `ELBv2Client` accessors | medium | mitigate | All three delegate to the existing `loadAWS`; no new credential source, no static keys, no endpoint override. The operator's existing SSO profile governs blast radius. |
| T-16-01-05 | Information disclosure | `KvVersion()` reading build info | low | accept | Build info exposes only the module path and version, which are already public in this repo. |
| T-16-01-SC | Tampering | Go module additions (`service/s3`, `service/ecs`, `service/elasticloadbalancingv2`) | medium | mitigate | All three are first-party `github.com/aws/aws-sdk-go-v2/service/*` modules from the same publisher already pinned in `kv/go.mod`; `go mod tidy` records checksums in `kv/go.sum` and the Go checksum database verifies them. No third-party or new-publisher dependency is introduced, so no legitimacy checkpoint applies. |
</threat_model>
