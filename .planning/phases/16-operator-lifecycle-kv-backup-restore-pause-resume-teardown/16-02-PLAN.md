<objective>
Build `kv backup` — the verified, self-contained artifact of everything that exists only in
AWS. This is Stage A's payload: three DynamoDB tables scanned to JSONL, the full S3 transcript
ledger as a key-preserving object tree, the external inventory (VoIP.ms DIDs, NAT EIP,
non-secret SSM parameters), a manifest with a SHA-256 per file, and a verification pass that
re-opens the zip and re-checks it.

Purpose: D-02 — the backup is designed for the destroy case from day one. Anything that
depends on the account surviving (native export to an in-account bucket, a KMS key held
inside the account) is precisely the thing that fails on the day the backup matters.

Output: `kv/internal/app/cmd/backup.go` with `NewBackupCmd`, the capture and verification
functions, its tests, and registration in `root.go`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AWS (DynamoDB / S3 / SSM) → local disk | user emails, access codes, and full conversation transcripts leave AWS and land in a plain file inside a git working tree |
| VoIP.ms API → kv process | third-party HTTPS endpoint authenticated with credentials resolved from env or SSM |
| kv process → operator terminal | warnings and errors are the only channel telling the operator what the artifact contains |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-02-01 | Information disclosure | the unencrypted zip on local disk containing transcripts and user email addresses | high | mitigate | `backups/` is gitignored in 16-01 before any artifact exists; Task 3 prints an unmissable closing block naming the contents and the unencrypted-by-design choice (D-08/D-14). Encryption with the in-account SOPS/KMS key is a prohibition, not an omission — a key destroyed with the account is worse than no key. |
| T-16-02-02 | Information disclosure | SecureString parameter values entering `external/ssm-params.json` | high | mitigate | `ExportSSMInventory` calls GetParameter only for String and StringList types and never with decryption enabled; a fake-driven test fails if decryption is requested; SecureString entries carry an explicit `valueOmitted` marker (D-14). |
| T-16-02-03 | Information disclosure | VoIP.ms credentials leaking into `external/voipms-dids.json` or an error string | high | mitigate | Reuses `resolveVoipmsCreds` and `ListInboundDIDs` unchanged, inheriting the existing never-log-params-or-URLs invariant; the degradation path emits a bare reason string with no request context. |
| T-16-02-04 | Tampering | a corrupted or truncated artifact reported as a successful backup | high | mitigate | Verification is default-on and re-reads the artifact, checking every SHA-256, every byte count, every row count, missing entries, and unexpected extra entries (D-09). This function is 16-10's abort gate. |
| T-16-02-05 | Repudiation | inability to tell which stack and commit an artifact came from | medium | mitigate | The manifest records git SHA, AWS account id, region, kv version, and the live-resolved table and bucket names (D-05). |
| T-16-02-06 | Denial of service | an unexpectedly large ledger producing an unusable artifact or an apparent hang | medium | mitigate | Elapsed time and artifact size are always printed and a warning fires above `backupSizeWarnBytes` (D-07); no partial-backup flag is offered, so the failure mode stays visible rather than silent. |
| T-16-02-07 | Spoofing | a substituted table or bucket being scanned | medium | mitigate | Names come only from `ResolveLiveTargets` and are recorded in the manifest for audit (D-05/D-10). |
</threat_model>
