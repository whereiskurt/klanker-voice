<objective>
Stage C's operator gate, and the only verification `kv destroy` will ever get before it is used
in earnest: run it with `--dry-run` against the live stack and read the report as the person who
would have to live with the real thing.

Purpose: `kv destroy` is irreversible by construction, so it can never be verified by running it.
The dry run is the entire proof. It exercises the real backup and the real verification against
real data, resolves the real ledger bucket and counts its real objects, and produces the real
report — while touching nothing. Reading that report carefully now is what makes the real command
trustworthy later.

Output: a reviewed dry-run report, a confirmed no-mutation check, an exercised typed-label
refusal, and a SUMMARY recording the ledger object count, the unit order, and the DID inventory
as the operator confirmed them.
</objective>

  <read_first>

    - .planning/phases/16-operator-lifecycle-kv-backup-restore-pause-resume-teardown/16-10-SUMMARY.md (the confirmation implementation as built)

  <action>
    Run each of the seven refusal and confirmation checks below with the operator, always with
    `--dry-run` present. Do not self-approve, and do not run `--no-backup` without `--dry-run`
    at any point. If the piped-exact-label behavior differs from what the operator wants, record
    it as a follow-up finding rather than patching it inside this checkpoint. Record all five
    refusal results and the piped-label decision into the SUMMARY.
  </action>
  <what-built>
    `--no-backup` skips the backup entirely and therefore requires the site label to be typed
    exactly. There is no `--yes` form and no yes-or-no form; an empty line, a wrong label, or a
    non-interactive stdin is a refusal. This is the only guard between a mistyped command and
    permanent transcript loss.
  </what-built>
  <how-to-verify>
    Every step below is run WITH `--dry-run` so that even a successful confirmation destroys
    nothing. Do not run `--no-backup` without `--dry-run` at any point in this checkpoint.

    1. Wrong label: `kv/bin/kv destroy --no-backup --dry-run` and type something that is not the
       site label. Confirm it refuses with a clear message and exits non-zero.
    2. Empty input: run it again and press enter on an empty line. Confirm it refuses.
    3. Yes-style input: run it again and type `yes`. Confirm it refuses — a yes is not a label.
    4. Non-interactive stdin: `kv/bin/kv destroy --no-backup --dry-run < /dev/null`. Confirm it
       refuses rather than proceeding on an EOF.
    5. Piped label: `echo kmv | kv/bin/kv destroy --no-backup --dry-run`. Decide with the operator
       whether a piped exact label should be accepted or refused, and record the decision. If the
       built behavior differs from what the operator wants, that is a finding for a follow-up
       task, not something to patch inside this checkpoint.
    6. Correct label interactively: run it once more and type the site label exactly. Confirm it
       proceeds past the confirmation, that the report marks the backup as skipped in the
       strongest terms, and that — because `--dry-run` is set — nothing was drained, deleted, or
       destroyed. Verify with the same baseline commands from Task 1.
    7. Mutual exclusion: `kv/bin/kv destroy --with-backup --no-backup --dry-run`. Confirm a usage
       error and a non-zero exit.

    Report back: which inputs were refused, what the piped-label behavior was and whether it is
    what you want, and confirmation that the skipped-backup warning was unmissable.
  </how-to-verify>
  <acceptance_criteria>
    - CLI: `kv destroy --no-backup --dry-run` with a wrong label exits non-zero with a refusal message
    - CLI: the same with an empty line exits non-zero
    - CLI: the same with `yes` typed exits non-zero
    - CLI: the same with stdin redirected from /dev/null exits non-zero

    - Recorded: the piped-exact-label behavior is documented in the SUMMARY along with the operator's decision on whether it is correct
  </acceptance_criteria>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator terminal → the irreversible command | this checkpoint deliberately runs the destroy command's real code paths with the destructive steps disabled |
| dry-run report → the operator's future decision to run the real thing | this report is the only evidence the real command will ever have |
| VoIP.ms inventory → the manual release step | numbers that cannot be bought back are listed here for a human to act on, or not |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-11-01 | Denial of service | accidentally running the real destroy while verifying the dry run | high | mitigate | Every invocation in both tasks carries `--dry-run`, the prohibition is stated in the frontmatter, and no-mutation is verified with independent AWS baseline commands before and after. |
| T-16-11-02 | Denial of service | a `--no-backup` guard that is weaker in practice than in the unit tests | high | mitigate | Task 2 exercises the refusal against the real binary across five distinct inputs including EOF, rather than trusting the fake-driven tests alone (D-32). |
| T-16-11-03 | Denial of service | an incorrect or incomplete DID inventory leading the operator to release the wrong number later | high | mitigate | The printed inventory is compared line by line against an independent VoIP.ms listing, with the two irreplaceable numbers called out by name (D-29). |
| T-16-11-04 | Tampering | a dry run that silently mutated something | high | mitigate | ECS counts, ledger object count and byte total, `git status`, and a `terragrunt plan` on the ledger unit are all checked after the run. |
| T-16-11-05 | Repudiation | an unreviewed report that reads as correct but omits something the operator needed | medium | mitigate | All four §6.3 statements are read individually and confirmed as factually correct and useful, not merely present. |
| T-16-11-06 | Information disclosure | another real backup artifact created on disk by the dry run | medium | mitigate | The artifact lands under the gitignored `backups/` directory; the SUMMARY records its size and path shape only, never its contents. |
</threat_model>
