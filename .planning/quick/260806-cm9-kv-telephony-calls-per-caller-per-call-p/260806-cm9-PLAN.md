<objective>
Add `kv telephony calls`: an operator call report answering **who called which number and
when**, built client-side from the telephony-edge CloudWatch log stream. Four views —
per-caller rollup (default), chronological per-call log, per-number rollup, and
new-caller/first-seen alerts. Raw caller numbers are always shown.

Purpose: this report has been produced twice as an ad-hoc Logs Insights query plus a
throwaway Python script during live operator sessions. Making it a first-class,
tested subcommand is the whole point of the task.

Output: `kv/internal/app/cmd/telephony_calls.go` + `telephony_calls_test.go`, registered
onto the existing `telephony` parent command.
</objective>

**One judgement call flagged for the operator (Task 3, `--view new`).** "First-ever
appearance" is only knowable from data you actually queried. Rather than issuing a second,
wider baseline Insights query (extra cost and latency), the new-caller view computes
first-seen over the *queried window* and flags callers whose first-seen falls within the
last `--new-within` of it. The rendered view prints the baseline it used, so the operator
can never mistake a narrow `--since` for a real first-ever claim. Usage shape:
`--since 720h --new-within 2h`.
