Read the file once first and match its EXISTING conventions exactly — do not invent a
new section shape. The conventions, confirmed during planning: a command group is a
level-1 heading of the form backtick-kv-space-group-backtick followed by an em dash and
a short tagline (see the `kv killswitch` group at line 347); each command inside it is a
level-3 heading holding the invocation in backticks, including any positional argument
(see `kv voipms order-did <did>` and `kv code create <code> --tier <tierId>`); flags are
a three-column table with the header row Flag / Default / Purpose; a blockquote starting
with a greater-than sign carries a warning that points at another page; groups are
separated by a horizontal rule.

Insert TWO new groups immediately after the `kv killswitch` group and before the
`kv telephony` group — that position is deliberate, because the killswitch section is
where an operator is already thinking about turning things off, and both new groups have
to disclaim any relationship to it.

Group A tagline: standing the whole stack down. Group B tagline: the data that only
exists in AWS.

Group A contains three level-3 entries: `kv pause`, `kv pause status`, `kv resume`.
Group B contains two: `kv backup`, `kv restore <zip>`.

Content per entry, from the verified-facts table in this plan's context block plus the
request's verified facts. Do not invent, do not embellish, do not soften:

- `kv pause` — flips the git-tracked paused flag in
  `infra/terraform/live/site/site.hcl`, commits and pushes it to `main`, dispatches
  `terragrunt-apply.yml`, then verifies every service reaches desired=running=0. Cost
  outcome: roughly 190 dollars a month down to roughly 60. Flags `--yes` and `--reason`
  per the table.
- `kv pause status` — READ-ONLY. Prints the current flag value plus live desired/running
  per service. Never commits, never pushes, never dispatches. Say that explicitly; it is
  the one entry in the group an operator can run without consequence.
- `kv resume` — the inverse, and additionally waits for the voice and auth ALB target
  groups to report healthy before printing success. A clean apply alone is not success.
- `kv backup` — writes `kmv-backup-<ISO8601>.zip` holding all three DynamoDB tables as
  JSONL, the full S3 transcript ledger, a secret-free external inventory (VoIP.ms DIDs,
  the NAT EIP, non-secret SSM parameters), and a `manifest.json` carrying a per-file
  SHA-256 and a per-table row count. Verification is ON by default and re-reads the
  written artifact; `--no-verify` opts out. State plainly that the artifact is
  UNENCRYPTED by design and contains PII — conversation transcripts and user email
  addresses — and that the default output directory `backups/` is gitignored.
- `kv restore <zip>` — destinations are resolved from LIVE terraform outputs, never from
  the archive's manifest, because bucket names carry a new random_id suffix after a
  rebuild. Ephemeral rows are filtered by default. Writes are idempotent and batched.
  `--dry-run` reports counts and writes nothing. A corrupted archive is refused, and the
  failing entry is named. Cover `--tables` / `--ledger` as the partial-restore selector
  (neither given = both).

Every one of the five entries links to its runbook for full detail: Group A entries to
`../ops/pause-resume.md`, Group B entries to `../ops/backup-restore.md`. Use real
anchors where you cite a specific section — the runbook headings were captured during
planning and are listed in this plan's context reading list. Because the published wiki
does not mirror `docs/ops/`, mention the repo path `docs/ops/` in the prose at least
once per group so a wiki reader with a dead link still knows where the file lives.

Include these four operator-critical gotchas. Put the prerequisite at the top of Group A
where it is unmissable and cross-reference it from Group B (it applies to all five):

1. PREREQUISITE: source the backend env contract with `set -a && . infra/.envrc && set +a`
   before running any of these. They resolve targets via `terragrunt output`, which needs
   those variables. Without it the failure is an opaque empty-bucket error that does not
   point at the cause — say so, because that error is the whole reason this note exists.
2. `kv pause` and `kv resume` run ONLY from `main` and refuse on ANY unclean working
   tree, INCLUDING untracked files — a stray build artifact blocks them entirely.
3. Both dispatch an apply gated by the `terraform-apply` environment's required-reviewer
   rule, so a full pause-then-resume round trip needs TWO manual approvals. Never start a
   pause you cannot finish. This belongs in a blockquote warning, matching the treatment
   the killswitch section gives its own trap.
4. Neither command ever touches the kill-switch — that is `kv killswitch`, a separate
   application-layer mechanism. Cross-link the existing killswitch section.

Also add matching rows to the "Command map" table (line 136) in the same relative order
as the body, so the two views stay consistent. The Reads / writes cell should name what
each actually touches — for pause/resume, the git-tracked site.hcl plus a dispatched
GitHub Actions apply plus live ECS/ALB reads; for backup/restore, the three DynamoDB
tables plus the S3 ledger plus VoIP.ms and SSM, against a local zip. The Needs cell
follows the table's existing vocabulary (AWS, repo) and must include the `infra/.envrc`
requirement and, for pause/resume, GitHub.

PROHIBITED: an entry for any command not registered in `kv/internal/app/cmd/root.go`;
any flag not in the verified-facts table; any claim about behaviour you did not read in
the runbooks, the request's verified facts, or this plan.
